## hazards

### 🔴 h1 — type error in `jest.integration.env.ts:105` (test hazard)

**what changed**: declapract regenerated `jest.integration.env.ts` (+64 lines). line 105 uses:

```ts
throw new Error(`...cant connect to database`, { cause: error });
```

**why it breaks**: the `{ cause }` second arg is `ErrorOptions`, available only in ES2022+. the repo `tsconfig.json` sets `target: es2020` and `lib: ["DOM"]`, so the `Error` constructor type accepts only 0-1 args.

```
jest.integration.env.ts(105,7): error TS2554: Expected 0-1 arguments, but got 2.
```

**how to verify**: `rhx git.repo.test --what types`

**candidate fixes** (for stone 3.1):
- add `ES2022` (or `ES2022.Error`) to `tsconfig.json` `lib`, or bump `target` — matches what the declapract template assumes; but `lib: ["DOM"]` is a repo-specific override, so this needs care
- OR drop the `{ cause: error }` option in the env file

### 🔴 h2 — dpdm circular dep via `helpful-errors` (cicd/lint hazard)

**what changed**: declapract added a new lint command `test:lint:cycles` (dpdm) + `.dpdmrc.yaml` (empty exclude). it now runs inside `test:lint`.

**why it breaks**: dpdm reports a cycle inside the third-party `helpful-errors` package:

```
node_modules/.../helpful-errors/dist/HelpfulError.js
  -> node_modules/.../helpful-errors/dist/withHelpfulError.js
```

- the cycle is *inside* a prod dependency (`helpful-errors`), not our src
- `.dpdmrc.yaml` and brief `rule.forbid.dpdm-exclude-change` forbid excluding prod deps
- `pnpm why` now resolves `helpful-errors` to 1.7.2/1.7.3; the dpdm log named 1.5.3 (possible stale transitive path) — worth confirming which version dpdm actually walks after a clean reinstall

**how to verify**: `rhx git.repo.test --what lint`

**candidate paths** (for stone 3.3):
- confirm whether the cycle persists in helpful-errors 1.7.x after clean node_modules
- if it's a genuine pre-existent cycle in a dependency we cannot fix, escalate to human (do NOT add to dpdmrc exclude)
