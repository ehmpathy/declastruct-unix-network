## defect inventory

### d1 — type error: `ErrorOptions` unavailable (`jest.integration.env.ts:105`)

- **what**: `test:types` failed with `TS2554: Expected 0-1 arguments, but got 2` at the `new Error(msg, { cause: error })` call.
- **how**: `git diff origin/main -- jest.integration.env.ts` shows the upgrade regenerated the env file and added `{ cause: error }` (an ES2022 `ErrorOptions`). `git diff origin/main -- tsconfig.json` shows `lib` was untouched — it kept a stale `lib: ["DOM"]`.
- **why**: `lib: ["DOM"]` fully replaces the default lib, so ES2022's `ErrorOptions` type was absent → `Error`'s constructor typed as max 1 arg. the peer repo `ehmpathy/declastruct-github` has **no `lib` field**, so it inherits `lib: ["es2023"]` (includes `ErrorOptions`) from `@tsconfig/node20`. our `lib: ["DOM"]` was a stale repo-specific override, not part of the declapract standard.
- **fix**: removed the `lib: ["DOM"]` override from `tsconfig.json` so the config inherits `es2023` from `@tsconfig/node20`. verified no repo code uses DOM globals (grep for `document|window|HTMLElement|fetch|localStorage|...` → no matches), so removal is safe. `test:types` now passes.

### d2 — 3 integration failures: shared-state hook mis-order (`dop.getOsUnixHostsFileLines.integration.test.ts`)

- **what**: 3 tests failed:
  - "parses all valid entries": expected 4, got 1
  - "empty hosts file": expected 0, got 1 (stale `server1` entry)
  - "only comments": `ENOENT` — `.test/.temp/hosts` absent (top-level `afterAll` ran before a case's `beforeAll`)
- **how**: `git diff origin/main -- src/access/sdks/osUnixHostsFile/` is empty — the test and sdk are **unchanged**. the only change is the `test-fns` bump (1.7.2 → 1.15.8).
- **why**: the failed test used raw jest `beforeAll` inside `given` blocks, which all wrote to a **single shared** `tempHostsPath`. the new `test-fns` changed `given`/`when` execution such that these raw hooks register/run out of order relative to the shared top-level `beforeAll`/`afterAll` → cases read each other's file state or find it already removed. the 7 green integration suites avoid this: they use `useBeforeAll` (test-fns-native, correctly ordered) with an **isolated temp dir per `given`** (see peer `dop.getOsUnixSystemdSocatServices.integration.test.ts`).
- **fix**: rewrote the test to match the established green pattern — `useBeforeAll` that returns a `scene`, one isolated temp dir + hosts file per `given` (via a `createIsolatedHostsFile` helper), per-`given` `afterAll` cleanup. **assertions unchanged** (same 4/0/0 expectations, same `toEqual` shapes); only the setup/isolation mechanism changed. all 16 integration tests now pass.

### d3 — dpdm circular dependency (`test:lint:cycles`)

- **what**: `test:lint:cycles` failed — dpdm found a cycle in `helpful-errors@1.5.3` (`HelpfulError.js ⇄ withHelpfulError.js`).
- **how**: the upgrade added the new dpdm cycle check; `declastruct@1.9.1` transitively pinned the cycle-prone `helpful-errors@1.5.3`.
- **why**: `helpful-errors@1.5.3` carries an internal import cycle, fixed upstream in `1.7.x`.
- **fix**: `set.package.upgrade declastruct → 1.9.2` pulls a cycle-free transitive `helpful-errors`. dpdm now reports zero cycles. no dpdmrc exclude added.

### d4 — acceptance required real `/etc/hosts` + sudo (`declastruct.acceptance.test.ts`)

- **what**: 2 acceptance `apply` tests failed with `sudo: a password is required`; a 3rd then failed on `plan is stale`.
- **how**: the acceptance asset hardcoded `via: '/etc/hosts'` and called `getDeclastructUnixNetworkProvider({}, ...)` with no repo paths, so the provider defaulted to the real `/etc/hosts` → the sdk's `needsSudo` branch shelled out to `sudo tee`.
- **why**: on `origin/main` this only ran in CI (passwordless sudo) or via `sudo -E` locally. per human direction, acceptance should run against an isolated temp dir like the integration suites — no sudo, no mutation of the real system.
- **fix**:
  - `resources.acceptance.ts` reads `ACCEPTANCE_ETC_HOSTS_PATH` / `ACCEPTANCE_SYSTEMD_UNITS_DIR` env vars and passes them into the provider (falls back to system paths when absent).
  - the test creates a temp dir + empty hosts file + systemd dir, hands those paths to the `declastruct` CLI subprocess via env, and verifies against the same temp paths. non-default paths ⇒ `needsSudo=false` ⇒ plain `tee`.
  - the idempotency test regenerates the plan before the second apply: declastruct's `assertPlanStillValid` rejects a **stale** plan (state drifts after the first apply). on main this masked only because the real `/etc/hosts` entry persisted across runs. the fresh plan against post-apply state is an already-satisfied no-op. all 4 acceptance tests now pass.

### d5 — depcheck flagged `rhachet-roles-ghlitch` unused (`test:lint:deps`)

- **what**: `test:lint:deps` (depcheck) flagged `rhachet-roles-ghlitch` as an unused devDependency.
- **how**: the upgrade added `rhachet-roles-ghlitch@0.2.4` to devDependencies but included it in neither the `prepare:rhachet` roles list nor the `.depcheckrc.yml` ignores.
- **why**: the role package is present as a peer of the other `rhachet-roles-*` deps but not referenced.
- **fix**: added `rhachet-roles-ghlitch` to `.depcheckrc.yml` ignores (per human direction), consistent with how the peer `rhachet-roles-*` deps are handled. `test:lint:deps` now passes.

## infrastructure feedback

- **declapract inconsistency**: `declapract-typescript-ehmpathy@0.49.4` ships a `jest.integration.env.ts` template that uses ES2022 `{ cause }` but does not enforce an ES2022-capable `lib` in the tsconfig it manages. repos with a legacy `lib: ["DOM"]` override break on `test:types`. the tsconfig template omits `lib` (defers to `@tsconfig/node20`), so the fix is to drop stale `lib` overrides — but declapract could detect/flag legacy `lib: ["DOM"]` overrides at upgrade time.
- **declapract inconsistency**: the upgrade added `rhachet-roles-ghlitch` to devDependencies but did not add it to `.depcheckrc.yml` ignores nor the `prepare:rhachet` roles list, so depcheck flags it as unused on a clean upgrade.
