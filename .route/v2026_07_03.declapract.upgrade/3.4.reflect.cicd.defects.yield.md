## d6 — stale acceptance docblock env var name → repo quirk

**classification**: repo quirk (self-inflicted, caught by self-review).

- the `.note` docblock in `declastruct.acceptance.test.ts` named `ACCEPTANCE_ETC_HOSTS_PATH` / `ACCEPTANCE_SYSTEMD_UNITS_DIR` while the code injects `ACCEPTANCE_ROOT`.
- **origin/main lens**: origin/main never carried those names — its docblock read `.note = requires sudo`. the stale names were introduced *and corrected* entirely within this branch. the d4 fix's first draft used two asymmetric env vars; the human then directed a single `ACCEPTANCE_ROOT` + fail-loud design, the code was updated, but the docblock lagged one iteration behind.
- **why it is a repo quirk, not a practice bug**: declapract ships no acceptance docblock template for this domain-specific test; the drift is a local author artifact of this repo's own iterative fix, not an inherited practice defect. no other repo would inherit it.
- **not an adoption candidate**: the sandbox pattern (env-injected root for privileged-resource acceptance tests) was already captured as an adoption candidate in `3.2.reflect.test.defects.yield.md` (d4). d6 is merely a comment that lagged the code; there is no new pattern to adopt.

**fix** (already applied in 3.3): rewrote the docblock to name `ACCEPTANCE_ROOT` and its `ROOT/etc` derivation; verified format + acceptance (4/4 green); committed `cont(test): correct stale acceptance docblock env var name`; cicd green.
