# 3.2.reflect.test.defects.yield

## purpose

classify each test defect from `3.1.repair.test.defects.yield.md` for feedback to infrastructure.

## classifications

| defect | classification | rationale |
|--------|---------------|-----------|
| d1 — `ErrorOptions` type error | **repo quirk** (+ practice-improvement note) | the stale `lib: ["DOM"]` override was local to this repo |
| d2 — integration hosts hook mis-order | **repo quirk** (+ adoption candidate for the fix) | the shared-state test pattern was local; the isolation fix is broadly good |
| d3 — dpdm cycle in `helpful-errors@1.5.3` | **repo quirk** (resolved by upgrade) | pre-existent transitive dep cycle, fixed upstream |

---

## d1 — `ErrorOptions` type error → repo quirk

**classification**: repo quirk, with a practice-improvement suggestion.

- the root cause was a **repo-local** stale `lib: ["DOM"]` override in `tsconfig.json`. the declapract tsconfig template omits `lib` (defers to `@tsconfig/node20` ⇒ `es2023`), so a fresh repo would not hit this.
- the peer repo `ehmpathy/declastruct-github` has no `lib` field and compiles fine — which marks this as a local artifact, not a shipped practice defect.

**practice-improvement note (nitpick, not a bug)**: declapract's `jest.integration.env.ts` template uses ES2022 `{ cause }`. declapract could optionally **detect + flag** legacy `lib: ["DOM"]` overrides at upgrade time, since they silently break the ES2022 template. this is an enhancement, not a defect in the shipped practice.

## d2 — integration hosts hook mis-order → repo quirk

**classification**: repo quirk; the fix is an adoption candidate.

- the failed test used raw jest `beforeAll` against a single shared temp file — a **repo-local** anti-pattern. the 7 peer integration suites in this same repo already use the correct `useBeforeAll` + isolated-dir pattern, so this was a lone straggler, not a shipped practice.
- **adoption candidate**: "isolated temp dir per `given` via `useBeforeAll`" is the robust pattern under the current `test-fns`; worth a nudge everywhere (already the norm in this repo's other suites).

## d3 — dpdm cycle → repo quirk (resolved by upgrade)

**classification**: repo quirk, self-resolved.

- the cycle lived in a **third-party** transitive `helpful-errors@1.5.3` that the prior `declastruct@1.9.1` pinned. upstream fixed it in 1.7.x. the `declastruct` bump to 1.9.2 pulled the fixed version.
- not a declapract practice defect: the new `test:lint:cycles` check behaves as intended — it correctly surfaced a real (pre-existent) cycle. the practice is sound; the dep was stale.

## d4 — acceptance sudo + stale plan → repo quirk

**classification**: repo quirk; the temp-dir fix is an adoption candidate.

- the acceptance test's dependence on the real `/etc/hosts` + sudo is **specific to this repo's domain** (unix network management). no generic practice mandates it.
- the stale-plan failure stems from `declastruct@1.9.2`'s new `assertPlanStillValid` guard — an intended upstream behavior, not a practice defect.
- **adoption candidate**: run acceptance against an isolated temp sandbox (env-injected paths) rather than a mutation of the real host — a broadly good pattern for any declastruct provider whose resources touch privileged system state.

## d5 — depcheck unused `rhachet-roles-ghlitch` → practice bug

**classification**: practice bug in declapract-typescript-ehmpathy.

- the upgrade added `rhachet-roles-ghlitch@0.2.4` to `devDependencies`; the `prepare:rhachet` roles list does **not** include `ghlitch`, and `.depcheckrc.yml` does **not** ignore it. so a clean upgrade leaves `test:lint:deps` red out of the box.
- the other `rhachet-roles-*` / `rhachet-brains-*` deps are all present in the depcheck ignore list; `ghlitch` was omitted — an inconsistency in the shipped practice.

**gh search citations**:
- `gh search code --repo ehmpathy/declapract-typescript-ehmpathy --filename .depcheckrc.yml "rhachet-roles"` → the shipped template `src/practices/lint/best-practice/.depcheckrc.yml` ignores exactly 4 role packages: `rhachet-roles-bhrain`, `-bhuild`, `-ehmpathy`, `-rhachet`. **ghlitch is absent.**
- `gh search code --repo ehmpathy/declapract-typescript-ehmpathy "ghlitch"` → **no matches** (declapract never references ghlitch).
- `gh search code --repo ehmpathy/declapract-typescript-ehmpathy "prepare:rhachet"` → shipped `src/practices/rhachet/best-practice/package.json` roles list is `mechanic behaver driver reviewer librarian ergonomist architect dispatcher` — **no ghlitch role**.

so `rhachet-roles-ghlitch` lands as a devDep via the `rhachet init` flow, but declapract neither lists it as a prepared role nor ignores it in depcheck → `test:lint:deps` fails out of the box on any repo that adopts the upgrade.

**recommended fix upstream**: add `rhachet-roles-ghlitch` to declapract's `src/practices/lint/best-practice/.depcheckrc.yml` alongside the other four role packages (or stop the addition of the ghlitch dep unless the ghlitch role is in the `prepare:rhachet` roles list).

## summary

- **4 repo quirks** (d1–d4): local artifacts or intended upstream behavior; not defects other repos should inherit.
- **1 practice bug** (d5): declapract adds `rhachet-roles-ghlitch` without a matched depcheck-ignore entry — other repos will hit the same red `test:lint:deps` on upgrade.
- **2 adoption candidates** (d2, d4 fixes): isolated-temp-dir test setup; env-injected temp paths for privileged-resource acceptance tests.
