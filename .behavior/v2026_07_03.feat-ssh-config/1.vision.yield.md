# 1.vision — declaratively manage ssh aliases

> illustrate the world when `declastruct-unix-network` can declaratively manage a
> local ssh keypair **and** a `~/.ssh/config` host block, symmetric with how it
> already manages `/etc/hosts` host aliases and `systemd-socat` port aliases.

---

## the proposed contract

**two** new declared resources, both beside the extant unix-network resources:

1. `DeclaredUnixSshKeypair` — mints/holds a local key via `ssh-keygen`.
2. `DeclaredUnixSshAlias` — the `~/.ssh/config` `Host` block, which **references**
   the keypair by ref.

```ts
// DeclaredUnixSshKeypair.ts
export interface DeclaredUnixSshKeypair {
  /**
   * .what = mechanism used to mint/manage the keypair
   */
  via: 'ssh-keygen';

  /**
   * .what = the private key path (the `-f` target) — the natural unique key
   */
  uri: string; // e.g. '~/.ssh/declastruct-demo'

  /**
   * .what = the key algorithm
   */
  algorithm: 'ed25519' | 'rsa';

  /**
   * .what = the key comment (the `-C` value)
   */
  comment: string;

  /**
   * .what = the `.pub` content line, e.g. 'ssh-ed25519 AAAA... comment'
   * .note = @metadata -> only known after mint; the aws authorized-key resource
   *         consumes this. the `.pub` PATH is derivable as `${uri}.pub`, so only
   *         the content (which must be read) is stored.
   */
  publicKey?: string;
}

export class DeclaredUnixSshKeypair
  extends DomainEntity<DeclaredUnixSshKeypair>
  implements DeclaredUnixSshKeypair
{
  public static unique = ['via', 'uri'] as const;
}
```

```ts
// DeclaredUnixSshAlias.ts
export interface DeclaredUnixSshAlias {
  /**
   * .what = mechanism used to manage the alias
   */
  via: '~/.ssh/config';

  /**
   * .what = the host alias label you type after `ssh` (the `Host` line)
   */
  from: string; // e.g. 'grove.ehmpathy'

  /**
   * .what = the connection target (the `HostName` + `Port` lines)
   */
  into: UnixEndpoint; // { host: 'localhost', port: 2222 }

  /**
   * .what = the ssh login user (the `User` line)
   */
  user: string; // e.g. 'ec2-user'

  /**
   * .what = ref to the keypair whose private path becomes the `IdentityFile`
   */
  key: RefByUnique<typeof DeclaredUnixSshKeypair>;
}

export class DeclaredUnixSshAlias
  extends DomainEntity<DeclaredUnixSshAlias>
  implements DeclaredUnixSshAlias
{
  public static unique = ['via', 'from'] as const;
  public static nested = { into: UnixEndpoint };
}
```

`UnixEndpoint { host, port }` is the same shape as the extant `UnixPortEndpoint`
(`DeclaredUnixPortAlias.ts:12`); we reuse it (or lift it to a shared name).

the family, after this lands:

| resource | via | unique | notable fields |
|----------|-----|--------|----------------|
| `DeclaredUnixHostAlias` | `/etc/hosts` | `via,from` | `into` (ip) |
| `DeclaredUnixPortAlias` | `systemd-socat` | `via,from` | `into` endpoint |
| **`DeclaredUnixSshKeypair`** (new) | `ssh-keygen` | `via,uri` | `algorithm`, `comment`, `publicKey` (readonly) |
| **`DeclaredUnixSshAlias`** (new) | `~/.ssh/config` | `via,from` | `into` endpoint, `user`, `key` → ref |

## the outcome world

### before

the local half of the ssh-tunnel flow is imperative. today bash wrappers
(`use.ssh.tunnel.sh`, `aws.ssh.config.sh`) mint the key and hand-write a `Host`
block into `~/.ssh/config`:

```bash
# imperative — mint key + append/edit the block by hand
ssh-keygen -t ed25519 -f ~/.ssh/declastruct-demo -N '' -C grove.ehmpathy
cat >> ~/.ssh/config <<EOF
Host grove.ehmpathy
  HostName localhost
  Port 2222
  User ec2-user
  IdentityFile ~/.ssh/declastruct-demo
EOF
```

fragile: re-runs duplicate the block, key mint is not idempotent-safe by hand,
and the config drifts from any declared intent.

### after

both halves become declared resources in one wish array:

```ts
const keypair = DeclaredUnixSshKeypair.as({
  via: 'ssh-keygen',
  uri: '~/.ssh/declastruct-demo',
  algorithm: 'ed25519',
  comment: 'grove.ehmpathy',
});

DeclaredUnixSshAlias.as({
  via: '~/.ssh/config',
  from: 'grove.ehmpathy',
  into: { host: 'localhost', port: 2222 },
  user: 'ec2-user',
  key: { via: 'ssh-keygen', uri: '~/.ssh/declastruct-demo' }, // ref → keypair
});
```

`declastruct apply` findserts the key (mints only if absent, never overwrites),
then finds-or-replaces the `Host grove.ehmpathy` block idempotently — every other
host left untouched. the alias's `IdentityFile` is **derived** from the keypair's
private `uri`.

### the aha moment

after one `declastruct apply`, this:

```
ssh grove.ehmpathy
```

does the work of `ssh -p 2222 -i ~/.ssh/declastruct-demo ec2-user@localhost` — and
`scp`, `rsync`, `git`, and VS Code remote all inherit the same alias, since they
read `~/.ssh/config` too.

> one memorable name instead of a fistful of flags — declared once, converges
> idempotently, re-apply is a safe no-op instead of a duplicate.

and the keypair's readonly `publicKey` feeds the aws `DeclaredAwsEc2SshKeyAuthorized`
resource, so a consumer wish like `use.ssh.tunnel.ts` declares the **entire** flow
across two providers — exactly the shape `use.vpc.tunnel.ts` already uses.

## user experience

### usecases

- **declare a tunnel alias** — `ssh grove.ehmpathy` reaches a box through a
  pre-bound ssm/vpc tunnel bound at `localhost:2222`.
- **declare a direct-host alias** — `ssh box` reaches a real hostname/ip with a
  chosen user + declared key.
- **mint-or-reuse a key** — the keypair findserts: minted once, reused forever,
  never clobbered.
- **converge config** — re-run `apply` any time; the key and the block are both
  idempotent.

### contract inputs & outputs

- **input** = a `DeclaredUnixSshKeypair` + a `DeclaredUnixSshAlias` desired-state.
- **output** = the reconciled key on disk and the reconciled `Host` block.
- **operations** (mirror hostAlias): `getOne*`, `getAll*`, `set*`
  (findsert + upsert) per resource, each wrapped in a dao and registered in the
  provider.

### timeline

1. author both resources in a wish array (keypair first — the alias refs it).
2. `declastruct apply` → key findserted (mint if absent) → block finds-or-replaces.
3. `ssh grove.ehmpathy` works immediately; subsequent applies are no-ops.

## mental model

- **to a friend**: "infrastructure-as-code for your `~/.ssh/config` — you describe
  the host and key you want, and it edits the files for you, safely and repeatably."
- **analogy**: same as the extant `/etc/hosts` alias management, one file over.
  `/etc/hosts` maps a name → ip; `~/.ssh/config` maps an alias → a full ssh recipe
  (host, port, user, key).
- **their terms vs ours**: users say "ssh alias" / "Host block" / "ssh key". we say
  `DeclaredUnixSshAlias`, `via`, `from`, `into`, `DeclaredUnixSshKeypair`. `from`/`into`
  keep parity with our other resources even though ssh users say "Host"/"HostName".

## evaluation

### how well it solves the goal

- fully removes the imperative key-mint **and** `~/.ssh/config` writer from the
  tunnel flow — end-to-end declarative across both providers.
- symmetric with extant conventions → low cognitive cost, easy to review.
- idempotent discipline matches the proven `/etc/hosts` path
  (`setUnixHostAlias` at `src/domain.operations/hostAlias/setUnixHostAlias.ts:16`).

### pros

- two small resources, each idempotent, composable via ref.
- `key` as a ref (not a raw path) makes the keypair the single source of truth —
  the aws side and the alias both read from it.
- reuses the whole extant scaffold: dobj → sdk → operations → dao → provider →
  contract export.

### cons / tradeoffs

- `from`/`into` reads slightly forced for ssh (`Host`/`HostName` are the native
  words) — see "what is awkward".
- `~/.ssh/config` is richer than `/etc/hosts` (comments, `Match`, includes,
  indentation, case-insensitive keywords) so the parser is harder than the
  hosts-file one.
- the keypair shells out to `ssh-keygen` — one imperative boundary, wrapped as a
  declared findsert (same shape as the extant sdks that shell out).

### edgecases & pit-of-success

- **key already present** → findsert returns it untouched; never overwrite an
  extant private key (data-loss guard).
- **duplicate `Host` blocks in the file** → get is deterministic: first-match wins
  (ssh's own semantics) and that block is replaced.
- **block among comments / custom indentation** → replace preserves the other
  hosts, never clobbers unrelated lines (same discipline as
  `replaceOsUnixHostsFileEntry`).
- **`~` expansion** in `uri` / config path → expand against `$HOME`.
- **acceptance safety** → follow the extant sandbox rule: never silently touch the
  real `~/.ssh/config` or real `~/.ssh` keys; require an explicit `ACCEPTANCE_ROOT`
  mirror or opt-in `ACCEPTANCE_AGAINST_HOST=true`, per
  `src/contract/sdks/.test/assets/resources.acceptance.ts:24`.

## decisions locked with the wisher

these were the open scope/shape calls; each is now settled:

| decision | choice |
|----------|--------|
| keypair in scope? | **yes** — two resources, keypair + alias |
| how the alias carries the key | **`key` = ref to keypair**; `IdentityFile` derived from `keypair.uri` |
| `into` shape | **`{ host, port }` endpoint** (folds the old top-level `port` in) |
| `from` shape | **plain string label** (ssh's `Host` alias is a name, not a socket) |
| `user` | **required** (always known in a declared flow) |
| `via` on both resources | **kept** (`'ssh-keygen'` + `'~/.ssh/config'`) for symmetry |
| `proxyCommand` | **dropped** — strategy is a pre-bound tunnel; ssh dials `localhost` directly, no proxy needed |
| public key model | **readonly `publicKey` content** only; `.pub` path derivable as `${uri}.pub` |
| field for algorithm | **`algorithm`** (not `type`) |
| configurable config path | **yes** — add `sshConfigPath` to `ContextUnixNetwork.osUnixNetwork.repo` (acceptance safety demands it) |
| delete support | **yes** — the daos wire a real `delete`: remove the `Host` block / remove the key files. diverges from the twin's `delete: null` |
| endpoint type | **lift `UnixPortEndpoint` → shared `UnixEndpoint`** and reuse for `into` |

## groundwork

### external research

the wish references `~/.ssh/config` (OpenSSH) and `ssh-keygen`. key constraints I
lean on (OpenSSH `ssh_config(5)` + `ssh-keygen(1)`, widely documented):

- config is a sequence of `Host <pattern>` blocks; keywords are indented by
  convention (whitespace-insignificant) and **case-insensitive**.
- ssh applies the **first obtained value** per keyword → the first `Host` block
  that matches wins. this justifies "first-match wins" in `getOne`.
- `ssh-keygen -t ed25519 -f <path> -N '' -C <comment>` mints a non-interactive,
  no-passphrase keypair and writes `<path>` + `<path>.pub`.

> not independently re-checked against live man pages this session; these are
> stable, well-known behaviors. flagged as `[research]` above before the parser
> and the `ssh-keygen` sdk are built.

### internal research

verified the extant pattern this mirrors (files + lines):

  pattern (`UnixPortEndpoint`, `:12`) + optional `uri?` metadata (`:25`) — the

- **contract exports** — `src/contract/sdks/index.ts:7` re-exports every dobj +

so the vision extends a well-established internal pattern; no new architecture,
only two resources that reuse the dobj → sdk → operations → dao → provider →
contract spine, plus a `ssh-keygen` sdk alongside the config-file sdk.

## what is awkward

- **`from`/`into` vs `Host`/`HostName`**: symmetry with the other resources wins,
  but ssh users think in `Host`/`HostName`. a small translation tax on every read.
- **`via` is heterogeneous**: `'~/.ssh/config'` (a file path) on the alias vs
  `'ssh-keygen'` (a mechanism) on the keypair vs `'/etc/hosts'` / `'systemd-socat'`
  on the twins. the field is present everywhere for symmetry, but its sense shifts
  between path and mechanism.
- **the keypair shells out**: `ssh-keygen` is an imperative boundary. wrapped as a
  declared findsert, it fits the extant "sdk that shells out" pattern, but it is
  the one place we run an external binary to mint state.
- **ssh config parse depth**: `~/.ssh/config` supports `Match`, `Include`, and
  wildcard patterns. a scope to plain `Host <exact-alias>` blocks keeps this
  tractable but means we deliberately do **not** handle `Match`/wildcard/`Include`
  — an accepted limitation to state up front.
