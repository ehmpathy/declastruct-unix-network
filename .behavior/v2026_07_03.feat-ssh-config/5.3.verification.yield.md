### gap found + fixed at buttonup

the acceptance wish (`resources.acceptance.ts`) already declared all four
resources (host, port, keypair, ssh alias), so plan+apply exercised the two new
ssh resources end-to-end. but the acceptance **assertions** only verified the
host + port resources — the keypair and ssh alias were applied yet never
asserted. per the buttonup mandate, closed the gap now:
- plan test: assert the keypair + ssh alias resources appear in the plan
- apply test: read back via the provider that the keypair minted (algorithm
  ed25519, publicKey `ssh-ed25519`) and the ssh alias block wrote (port 2222,
  user ec2-user)

### l3-round gaps closed + a latent bug fixed at cause

a second review round (strong-brain l3 reviewers) surfaced further real gaps in
the acceptance journey. all closed:
- **portAlias never verified on apply** → added a provider read-back that asserts
  the systemd-socat unit applied (from 59432, into 59433)
- **del\* ops uncovered** → added a `del is issued` journey: set → verify exists
  → del ssh alias + keypair → verify both `get` return null (del\* are public sdk)
- **idempotency test had no assertions** → the re-plan is now asserted to be a
  pure no-op (every change `KEEP`), plus a deterministic plan-structure snapshot
- **plan test lacked a structure snapshot** → added a `{class, action}` snapshot
- **acceptance alias snapshot lacked `key`** → added `key.via` so the keypair
  ref is visible end-to-end (key.uri is the non-deterministic sandbox path)

**latent bug found + fixed at cause:** the new idempotency KEEP assertion caught
a real non-idempotency in `DeclaredUnixPortAlias` — its autogenerated `uri` (the
systemd unit path) was read back into remote but never in desired, so a re-plan
reported a false perpetual `UPDATE`. fixed at cause: `uri` is now
`static readonly` (excluded from the equivalence diff), the same treatment
`keypair.publicKey` gets for its autogenerated metadata. the old test never
re-planned (it re-applied the same plan file), so it never surfaced this. now all
four resources re-plan as `KEEP` — proven by the idempotency snapshot.
